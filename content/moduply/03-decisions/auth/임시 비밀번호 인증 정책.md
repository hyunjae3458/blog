# 임시 비밀번호 인증 정책

## 날짜
- 2026-06-27

## 배경
- 비밀번호 찾기 기능에서 임시 비밀번호를 발급해야 한다.
- 임시 비밀번호는 3분 동안만 유효해야 한다.
- 임시 비밀번호 발급 후 사용자는 임시 비밀번호로 로그인할 수 있어야 한다.
- 임시 비밀번호가 살아 있는 동안 기존 비밀번호 로그인은 막기로 했다.
- 3분이 지나면 기존 비밀번호로 다시 로그인 가능해야 한다.

## 검토한 방식
### DB 비밀번호를 임시 비밀번호로 변경
- 임시 비밀번호 발급 시 DB의 `encodedPassword`를 임시 비밀번호로 덮어쓴다.
- 3분 후 기존 비밀번호로 복구해야 한다.

문제:
- Redis TTL 만료 이벤트만으로 DB 원복을 처리하면 이벤트 유실 가능성이 있다.
- 애플리케이션 재시작, Redis 설정 누락, 장애 상황에서 원복이 보장되지 않는다.
- 원래 비밀번호 해시를 Redis에 저장하는 것도 보안과 복구 신뢰성 측면에서 부담이 있다.
- lazy restore + scheduler 보정 방식이 필요해져 구현 복잡도가 높아진다.

### Redis 임시 비밀번호 우선 인증
- DB 비밀번호는 변경하지 않는다.
- Redis에 인코딩된 임시 비밀번호를 3분 TTL로 저장한다.
- 로그인 시 Redis를 먼저 조회한다.
- Redis에 임시 비밀번호가 있으면 해당 값을 인증 비밀번호로 사용한다.
- Redis에 임시 비밀번호가 없으면 DB 비밀번호를 인증 비밀번호로 사용한다.

장점:
- DB 비밀번호 원복 로직이 필요 없다.
- Redis TTL이 끝나면 자연스럽게 기존 DB 비밀번호 로그인이 다시 가능해진다.
- 정책이 단순하다.

단점:
- Redis 장애 시 임시 비밀번호 정책에 직접 영향이 있다.
- Redis에 임시 비밀번호가 있는 동안 기존 비밀번호 로그인은 의도적으로 막힌다.

## 결정
- DB 비밀번호는 임시 비밀번호로 변경하지 않는다.
- Redis에 인코딩된 임시 비밀번호를 저장한다.
- Redis key는 `RedisKeyPolicy.PASSWORD_RESET` 정책을 사용한다.
- TTL은 3분으로 둔다.
- 로그인 시 `ModuPlyUserDetailsService`에서 Redis를 먼저 조회한다.
- Redis에 값이 있으면 Redis의 임시 비밀번호를 사용한다.
- Redis에 값이 없으면 DB의 기존 비밀번호를 사용한다.
- 비밀번호 변경 성공 시 Redis 임시 비밀번호 key를 삭제한다.

## 보류한 부분
- `POST /api/auth/reset-password`의 CSRF 검증 정책은 임시로 ignore 처리했다.
- 비밀번호 재발급 API의 CSRF 정책은 추후 팀 논의 후 다시 정리한다.
- 임시 비밀번호 검증 화면과 일반 로그인 화면의 프론트 흐름은 실제 동작 확인 후 보완한다.

## 관련 구현
- `AuthService.resetPassword`
- `TempPasswordUtil`
- `ModuPlyUserDetailsService.loadUserByUsername`
- `UserService.updateUserPassword`
- `RedisKeyPolicy.PASSWORD_RESET`
- `RedisUtil`
