# 계층적 권한 적용 정리

## 결정
현재는 `AuthService`에서 `RoleHierarchy`를 사용해 `Authentication`의 권한을 펼치고, WebSocket 인가 설정의 role hierarchy 적용 여부는 리팩토링 단계에서 다시 논의한다.

## 논의 내용
`RoleHierarchyConfig`는 이미 `ADMIN -> USER` 계층을 정의하고 있다.

- HTTP 메서드 보안은 `MethodSecurityExpressionHandler`에 등록된 `RoleHierarchy`를 사용한다.
- WebSocket은 별도의 `AuthorizationChannelInterceptor`를 사용하므로, HTTP와 같은 방식으로 계층이 자동 적용된다고 가정하면 안 된다.

즉, HTTP와 WebSocket은 권한 해석 지점이 다르다.

## 이유
`AuthService`에서 raw authority만 넣으면 인증 객체는 사용자 본래 권한만 가진다. 이 방식이 인증과 인가 책임을 분리하기 더 좋다.

다만 현재 WebSocket 인가 흐름은 별도 설정을 쓰므로, WebSocket에서 `ADMIN`이 `USER` 권한도 가진 것으로 해석되게 하려면 다음 중 하나가 필요하다.

- `AuthService`에서 `RoleHierarchy`를 미리 펼친다
- WebSocket 인가 설정에 `RoleHierarchy`를 직접 연결한다
