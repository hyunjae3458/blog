# 실무형 확장 구조

## 목적
실제 운영 서비스와 장애 대응까지 고려한 목표 구조다. 현재 프로젝트에서는 즉시 도입하지 않고, 포트폴리오 설명과 장기 확장 방향으로 둔다.

## 구조

```text
Internet
  ↓
Route53
  ↓
ALB + ACM : 443
  ├─ /api/**    → api target group
  ├─ /ws        → realtime target group
  └─ /api/sse   → realtime target group

ECS / EC2
  ├─ Spring API #1: t3.large
  ├─ Spring API #2: t3.large
  ├─ Realtime #1: t3.large
  ├─ Realtime #2: t3.large
  └─ Batch Worker #1: t3.medium

Managed / Dedicated
  ├─ RDS PostgreSQL: db.m7g.large Multi-AZ
  ├─ ElastiCache Redis: primary + replica
  └─ Kafka: broker 3대 또는 MSK/Confluent
```

## API와 Realtime을 나누는 이유

| 구분 | API 서버 | Realtime 서버 |
|---|---|---|
| 주요 엔드포인트 | `/api/**` | `/ws`, `/api/sse` |
| 연결 시간 | 짧음 | 김 |
| 주요 병목 | CPU, DB query, transaction | connection 수, memory, network |
| 스케일 기준 | RPS, p95 latency | 동시 연결 수 |

처음에는 같은 Spring Boot 앱을 여러 서버에 띄우고 ALB path routing만 분리한다.

```text
/api/**  → api target group
/ws      → realtime target group
/api/sse → realtime target group
```

현재 코드에서 API와 Realtime 클래스가 서로 의존하므로, 처음부터 profile로 Bean을 끄면 안 된다. 먼저 트래픽만 분리하고, 이후 이벤트 기반으로 의존성을 줄인 뒤 profile 분리를 검토한다.

## 실무형 전환 방향

```text
Redis EC2 → ElastiCache Redis primary + replica
Kafka 단일 broker → Kafka 3 broker 또는 MSK
Spring App 단일 역할 → API / Realtime / Batch 역할 분리
RDS 단일 AZ → RDS Multi-AZ
```

## 예상 비용

| 항목 | 월 예상 |
|---|---:|
| ALB + Public IPv4 | 약 $35~50 |
| Spring API `t3.large` 2대 | 약 $120~180 |
| Realtime `t3.large` 2대 | 약 $120~180 |
| Batch Worker `t3.medium` 1대 | 약 $30~40 |
| RDS `db.m7g.large` Multi-AZ | 약 $250~450+ |
| ElastiCache Redis 2노드 | 약 $100~180 |
| Kafka EC2 3대 + EBS | 약 $150~300+ |
| 로그 / 데이터 전송 / 스냅샷 | 약 $50~150+ |
| 총합 | 약 $850~1,500+ |
