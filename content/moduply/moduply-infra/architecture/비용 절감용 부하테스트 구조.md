# 비용 절감용 부하테스트 구조

## 목적
1만명 트래픽 부하테스트를 위해 현재 단일 EC2 구조보다 병목을 더 명확히 관측할 수 있는 분산 구조를 만든다. 단, 부트캠프 프로젝트와 포트폴리오 목적이므로 Redis와 Kafka는 관리형이 아니라 EC2 단일 노드로 시작한다.

## 구조

```text
Internet
  ↓
ALB + ACM
  ↓
Spring App EC2 #1: t3.medium
Spring App EC2 #2: t3.medium
Spring App EC2 #3: optional
  ↓
RDS PostgreSQL: db.t4g.medium
Redis EC2: t3.small 또는 t3.medium
Kafka EC2: t3.medium
```

ECS 기준 구조:

```text
ECS Cluster: moduply-cluster
├─ Capacity Provider: moduply-app-cp
│  └─ ASG: moduply-app-asg
│     ├─ Spring EC2 #1
│     ├─ Spring EC2 #2
│     └─ Spring EC2 #3 optional
├─ Capacity Provider: moduply-redis-cp
│  └─ ASG: moduply-redis-asg
│     └─ Redis EC2 #1
└─ Capacity Provider: moduply-kafka-cp
   └─ ASG: moduply-kafka-asg
      └─ Kafka EC2 #1
```

## ECS Service

```text
moduply-app-service
- task definition: moduply-app-task
- capacity provider: moduply-app-cp
- desired count: 2~3
- ALB target group 연결

moduply-redis-service
- task definition: moduply-redis-task
- capacity provider: moduply-redis-cp
- desired count: 1
- ALB 연결 없음

moduply-kafka-service
- task definition: moduply-kafka-task
- capacity provider: moduply-kafka-cp
- desired count: 1
- ALB 연결 없음
```

## ASG 기준

```text
moduply-app-asg
- min: 2
- desired: 2
- max: 3

moduply-redis-asg
- min: 1
- desired: 1
- max: 1

moduply-kafka-asg
- min: 1
- desired: 1
- max: 1
```

## 예상 비용

| 항목 | 월 예상 |
|---|---:|
| ALB + Public IPv4 | 약 $35~50 |
| Spring App `t3.medium` 2대 | 약 $60~80 |
| Spring App 3대 사용 시 추가 | 약 $30~40 |
| Redis EC2 `t3.small` | 약 $15~20 |
| Kafka EC2 `t3.medium` + gp3 EBS | 약 $40~70 |
| RDS `db.t4g.medium` | 약 $45~80 |
| EBS / 로그 / 데이터 전송 | 약 $30~70 |
| 총합 | 약 $225~370+ |

## 장점
- Spring App을 2~3대로 늘려 ALB 기반 분산을 경험할 수 있다.
- Redis와 Kafka를 앱 서버에서 분리해 병목 분석이 쉬워진다.
- ElastiCache, MSK를 모두 쓰는 것보다 비용이 낮다.
- 포트폴리오에서 "비용 제약을 고려한 분산 설계"로 설명하기 좋다.

## 단점
- Redis EC2 단일 노드는 장애 시 Redis 전체 장애가 된다.
- Kafka 단일 broker는 실무형 고가용성 구성이 아니다.
- Redis/Kafka 설치, 재시작, 디스크, 모니터링을 직접 챙겨야 한다.
- `t3` 계열은 burstable이라 CPU credit을 확인해야 한다.
