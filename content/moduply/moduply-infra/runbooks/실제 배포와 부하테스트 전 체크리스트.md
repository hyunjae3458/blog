# 실제 배포와 부하테스트 전 체크리스트

## 비용 발생 리소스 생성 순서

실제 부하테스트 직전에 생성하거나 켠다.

```text
1. ACM 인증서 발급 및 검증
2. RDS PostgreSQL 생성
3. EC2 Launch Template 생성
4. ASG 생성
5. ECS Capacity Provider 생성
6. ECS Cluster에 Capacity Provider 연결
7. ECS Service 생성
8. ALB 생성
9. Target Group 생성 및 연결
10. Route53/DNS 연결
11. Redis/Kafka 실제 연결 확인
12. k6/JMeter 부하테스트 실행
```

## ALB

Listener:

```text
80  → 443 redirect
443 → HTTPS forward
```

Path routing:

```text
/api/sse  → realtime target group
/ws       → realtime target group
/api/*    → api target group
default   → api target group
```

현재 코드가 API/Realtime으로 완전히 분리되지 않았으면 처음에는 app target group 하나만 사용해도 된다. 이후 path routing을 추가한다.

## RDS

부하테스트용:

```text
db.t4g.medium
PostgreSQL
gp3 100GB 내외
```

상시 운영용:

```text
db.t4g.micro 또는 db.t4g.small
```

Spring Hikari 설정:

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 5~10
      minimum-idle: 1~2
```

Spring App 여러 대의 pool 합계를 RDS가 감당할 수 있어야 한다.

## EC2 ASG와 Capacity Provider

부하테스트용:

```text
moduply-app-asg: 2 / 2 / 3
moduply-redis-asg: 1 / 1 / 1
moduply-kafka-asg: 1 / 1 / 1
```

상시 운영용:

```text
moduply-app-asg: 1 / 1 / 1
moduply-redis-asg: 1 / 1 / 1
moduply-kafka-asg: 0 / 0~1 / 1
```

EC2가 ECS Cluster에 붙도록 Launch Template user data를 설정한다.

```bash
#!/bin/bash
echo ECS_CLUSTER=moduply-cluster >> /etc/ecs/ecs.config
```

ECS optimized AMI를 사용한다.

## Redis

환경변수:

```text
REDIS_HOST=실제 Redis private DNS
REDIS_PORT=6379
```

Redis task command:

```text
redis-server,--appendonly,yes
```

실제 데이터 유지를 원하면 `/data` 볼륨 마운트를 결정한다.

## Kafka

Spring 환경변수:

```text
SPRING_KAFKA_BOOTSTRAP_SERVERS=<Kafka EC2 private IP>:9092
MODUPLY_EVENT_TYPE=kafka
```

Kafka task 환경변수에서 반드시 바꿔야 할 값:

```text
KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://<Kafka EC2 private IP>:9092
```

현재 비용 절감용 구성은 Cloud Map 없이 `bridge` 모드와 Kafka EC2 private IP를 사용한다. ASG instance refresh 또는 EC2 교체가 발생하면 Kafka EC2 private IP가 바뀔 수 있으므로 App과 Kafka task 환경변수를 같이 갱신한다.

## 배치 메타 테이블

`prod`에서는 Spring Batch 스키마 자동 초기화를 끄고 있다.

```yaml
spring:
  batch:
    jdbc:
      initialize-schema: never
```

운영 DB에는 Spring Batch PostgreSQL 메타 테이블 DDL을 1회 적용해야 한다.

## 부하테스트 관측 지표

```text
ALB 5xx / target 5xx
ALB target response time
Spring CPU / memory
JVM heap / metaspace
API p95 latency
RDS CPU / connections / locks / slow query
Redis memory / evictions / command latency
Kafka consumer lag
EC2 CPU credit
```

목표 예시:

```text
API p95 latency < 300~500ms
Spring CPU < 60~70%
RDS CPU < 60%
Redis eviction 없음
Kafka consumer lag 누적 없음
```
