# 테스크 정의 기준

## 공통

```text
Launch type: EC2
Network mode: awsvpc
OS: Linux
CPU architecture: X86_64
```

Task Definition은 등록 후 직접 수정되지 않고 새 revision으로 관리된다. 리소스, 환경변수, 이미지, OS/Architecture 변경은 새 revision을 만들고 ECS Service가 새 revision을 쓰도록 업데이트한다.

## App Task

현재 앱은 이미 `1 vCPU / 1.5 GB` 수준에서 운영 중이므로, 상시 운영용이라고 해도 `0.5 vCPU / 1 GB`로 낮추는 것은 위험하다.

### Nginx 사이드카 유지 시

```text
Task size
- vCPU: 1
- Memory: 1.5 GB

Spring container
- CPU: 0.875 vCPU
- Memory soft limit: 1 GB
- Memory hard limit: 1.375 GB

Nginx container
- CPU: 0.125 vCPU
- Memory soft limit: 0.0625 GB
- Memory hard limit: 0.125 GB
```

### ALB 도입 후 Nginx 제거 시

```text
Task size
- vCPU: 1
- Memory: 1.5 GB

Spring container
- CPU: 1 vCPU
- Memory soft limit: 1 GB
- Memory hard limit: 1.5 GB
```

포트:

```text
8080 TCP
```

## Redis Task

```text
Task size
- vCPU: 0.25 vCPU
- Memory: 0.5 GB

Container resources
- CPU: 0.25 vCPU
- Memory soft limit: 0.25 GB
- Memory hard limit: 0.5 GB

Image:
redis:7.2-alpine

Port:
6379 TCP
```

Docker configuration:

```text
Entry point: 비움
Command: redis-server,--appendonly,yes
Working directory: 비움
```

`appendonly yes`는 Redis AOF 영속화 옵션이다. 실제 데이터 유지를 위해서는 나중에 `/data` 볼륨 마운트가 필요하다. 지금은 Task Definition만 준비하므로 볼륨은 설정하지 않는다.

## Kafka Task

```text
Task size
- vCPU: 1 vCPU
- Memory: 3 GB

Container resources
- CPU: 1 vCPU
- Memory soft limit: 2 GB
- Memory hard limit: 3 GB

Image:
confluentinc/cp-kafka:7.5.3

Port:
9092 TCP
```

Docker configuration:

```text
Entry point: 비움
Command: 비움
Working directory: 비움
```

단일 broker KRaft 모드 환경변수:

```text
KAFKA_BROKER_ID=1
KAFKA_NODE_ID=1
KAFKA_PROCESS_ROLES=broker,controller
KAFKA_CONTROLLER_QUORUM_VOTERS=1@localhost:9093
KAFKA_LISTENERS=PLAINTEXT://:9092,CONTROLLER://:9093
KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://<Kafka EC2 private IP>:9092
KAFKA_LISTENER_SECURITY_PROTOCOL_MAP=PLAINTEXT:PLAINTEXT,CONTROLLER:PLAINTEXT
KAFKA_INTER_BROKER_LISTENER_NAME=PLAINTEXT
KAFKA_CONTROLLER_LISTENER_NAMES=CONTROLLER
KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR=1
KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR=1
KAFKA_TRANSACTION_STATE_LOG_MIN_ISR=1
KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS=0
KAFKA_LOG_DIRS=/tmp/kraft-combined-logs
CLUSTER_ID=MkU3OEVBNTcwNTJENDM2Qk
KAFKA_HEAP_OPTS=-Xms1g -Xmx1g
```

주의:

```text
KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://<Kafka EC2 private IP>:9092
```

현재 비용 절감용 구성은 Cloud Map 없이 `bridge` 모드와 Kafka EC2 private IP를 사용한다. App 환경변수의 `SPRING_KAFKA_BOOTSTRAP_SERVERS`도 같은 private IP를 바라봐야 한다.

Kafka 데이터 유지를 위해 실제 운영 전 볼륨 마운트 전략을 다시 결정한다. 현재는 단일 broker 실시간 이벤트 전파 용도라 영속성보다 빠른 구성과 비용 절감을 우선했다.
