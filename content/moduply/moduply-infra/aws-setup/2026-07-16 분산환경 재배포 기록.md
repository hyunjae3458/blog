# 2026-07-16 분산환경 재배포 기록

## 한 줄 요약
> ALB + ACM + RDS + ECS EC2 Capacity Provider 기반으로 Spring App과 Redis를 분리 배포했고, 기존 단일 ECS EC2 구조에서 분산형 상시 운영 구조로 전환했다.

## 최종 배포 구조

```text
Internet
  ↓
Route 53
  ↓
ALB + ACM
  ├─ HTTP 80 → HTTPS 443 redirect
  └─ HTTPS 443 → moduply-app-instance-tg
        ↓
Spring App ECS Service
  └─ App ASG / App Capacity Provider

Spring App
  ├─ RDS PostgreSQL
  └─ Redis ECS Service
        └─ Redis ASG / Redis Capacity Provider
```

## 오늘 생성 / 연결한 리소스

```text
ALB
- HTTPS 443 리스너 구성
- HTTP 80은 HTTPS redirect 용도
- ACM 인증서 연결
- Route 53 A Alias 레코드로 도메인 연결

Target Group
- awsvpc 시도 시 IP 타입 target group 사용
- OAuth egress 문제 해결을 위해 App을 bridge로 전환하면서 Instance 타입 target group을 새로 생성
- 최종 App target group: moduply-app-instance-tg

RDS
- PostgreSQL 생성
- Spring App SG에서만 5432 접근 허용

ECS Cluster
- moduply-prod2-cluster
- Fargate 기본 클러스터로 생성 후 EC2 Capacity Provider 추가

ASG / Capacity Provider
- moduply-app-asg → moduply-app-cp
- moduply-redis-asg → moduply-redis-cp2
```

## 현재 네트워크 모드

```text
Spring App
- network mode: bridge
- host port: 8080
- target group: Instance 타입
- 이유: NAT Gateway 없이 Google OAuth 등 외부 API 호출 필요

Redis
- network mode: awsvpc
- Redis task private IP를 App 환경변수에 임시 반영
- 추후 Cloud Map 또는 내부 DNS로 고정 이름을 부여하는 것이 좋음
```

## 보안그룹 기준

```text
ALB SG
- inbound 80/443 from 0.0.0.0/0

Spring App SG
- inbound 8080 from ALB SG
- outbound all

Redis SG
- inbound 6379 from Spring App SG

RDS SG
- inbound 5432 from Spring App SG
```

## 운영상 주의

현재 상시 운영용은 App desired count가 1이므로 배포 중 무중단을 기대하면 안 된다.

```text
단일 App task 배포
→ 기존 task 종료 또는 target deregistration
→ 새 task healthy 전까지 순간 단절 가능
```

끊김을 줄이려면 다음 설정을 유지한다.

```text
ECS service health check grace period: 180초 권장
Target group success codes: 200-399
Target group health check path: /swagger-ui/index.html 또는 /v3/api-docs
Deregistration delay: 30초 수준
```

무중단에 가깝게 하려면 발표 전에는 App ASG와 App service를 2개 이상으로 올린다.

```text
App ASG desired: 2
App service desired: 2
```
