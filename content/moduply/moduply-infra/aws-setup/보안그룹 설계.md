# 보안그룹 설계

## 목표

외부에는 ALB만 공개하고, App/Redis/Kafka/RDS는 내부 통신만 허용한다.

```text
Internet
  ↓ 80/443
ALB
  ↓ 8080
Spring App
  ├─ 5432 → RDS
  ├─ 6379 → Redis
  └─ 9092 → Kafka
```

## Security Group

### moduply-alb-sg

Inbound:

```text
HTTP 80 from 0.0.0.0/0
HTTPS 443 from 0.0.0.0/0
```

Outbound:

```text
All traffic
```

### moduply-app-sg

Inbound:

```text
TCP 8080 from moduply-alb-sg
```

Outbound:

```text
All traffic
```

SSH가 필요하면 임시로만 연다.

```text
TCP 22 from 내 IP
```

### moduply-redis-sg

Inbound:

```text
TCP 6379 from moduply-app-sg
```

Outbound:

```text
All traffic
```

### moduply-kafka-sg

Inbound:

```text
TCP 9092 from moduply-app-sg
```

Outbound:

```text
All traffic
```

### moduply-rds-sg

Inbound:

```text
TCP 5432 from moduply-app-sg
```

Outbound:

```text
All traffic
```

## 주의

- Redis 6379와 Kafka 9092는 인터넷에 열지 않는다.
- RDS 5432도 인터넷에 열지 않는다.
- SSH 22는 필요할 때만 내 IP로 임시 허용한다.
- ALB만 public subnet에 두고, App/Redis/Kafka/RDS는 가능하면 private subnet에 둔다.
- NAT Gateway는 비용이 크므로 초기에는 public subnet + 제한된 SG 또는 VPC endpoint 전략을 비용과 함께 검토한다.
